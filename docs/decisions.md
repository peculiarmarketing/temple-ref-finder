# Decision log

Settled decisions. Read before changing behavior; these outrank the README when they conflict.

## 2026-08-20 (project start, all from Evan during planning)

- **Source order.** churchofjesuschristtemples.org first, general web search only as fallback when the gallery cannot fill the target.
- **Architecture.** Claude session + scripts. Claude does searching and visual judgment in-session; scripts do deterministic filesystem and network work. Manual trigger ("run the refs sweep"), no scheduler, no new API keys.
- **Target.** Top up every normal folder to 5-10 reference images total (existing images count). Raised from 3-5 by Evan on 20 Aug 2026, mid first full sweep. Scale within the range by clarity: 5 is enough only when the passes are clean, unobstructed views; when the best available images are marginal (edits, partial screening, soft light), keep hunting toward 10 so the drawing has enough good material.
- **Starred folders.** A trailing `*` on a TO DO folder name means under construction or announced-only, where a single official render is all that exists. No top-up. Empty starred folders get the best 1-2 renders from the site's Official section. Starred folders that already hold their render get a resolution check and a note, then move to READY (Evan confirmed 20 Aug).
- **Shortfall.** Under 5 passing images still moves to READY, with a note in the report explaining why (threshold was 3 until the target rose on 20 Aug 2026).
- **Obstruction tiers.** Minor occluders pass clean with no edit prompt; the line-art prompt handles them. Moderate occlusion or poor background contrast passes with a Nano Banana Pro prompt, minimal edits only. Heavy occlusion (backfill would be guesswork) fails by default; the detail-ref rescue (secondary images showing the hidden parts) is only for when the gallery has nothing better. **Tightened 20 Aug 2026 (Evan, second sweep, on two Ogden picks):** "minor" is ONLY what does not overlap the building fabric — fences/hedges below the building line, poles against sky, crowns fully beside the silhouette, at most one thin pole crossing the facade. Any foliage overlapping the building itself, including trees crossing the base line or covering lower-story stone, is at least moderate and MUST carry an edit prompt to remove it.
- **Detail refs on moderate edits (20 Aug 2026, Evan, second sweep).** NB Pro edits may attach extra reference images (the edit's `details` list) beyond the heavy-tier rescue case: attach one when the occluded element is unique rather than a repeating bay (entrance pavilion, corner junction) and another image in the same selection shows it clearly. In-photo repetition stays the primary fill instruction; prompts must name each image's role and tell the model to ignore the reference image's lighting and perspective, otherwise multi-image edits risk attribute bleed.
- **Corrections after placement (20 Aug 2026).** When a rule change forces a re-judgment of refs already sitting in READY, do NOT rewrite the original `report (auto).md` (the no-overwrite rule stands, and it is the record of what the first pass decided). Write `report correction (auto).md` beside it naming every reclassified image and why. The correction file supersedes the original wherever they disagree.
- **Working-file naming (20 Aug 2026).** Every working file written while judging, images AND scripts alike, must carry the temple slug in its name and live in a per-temple subdirectory. Two separate collisions proved this in one run: a re-audit agent was nearly fooled into judging Lindon crops as Deseret Peak because a shared scratchpad still held stale files named `a_left.jpg`, and two concurrent agents overwrote each other's mover script at the same generic path. Generic names in a shared scratchpad silently swap one temple's evidence, or one temple's file operations, for another's. This matters most when temples are audited in parallel.
- **Placeholders.** Folders named "untitled folder copy N" are always skipped.
- **Old tooling.** The Utah Temple Reference Picker HTML and the hf_ downloader are one-off experiments; ignored, built fresh.
- **Site facts (verified 20 Aug 2026).** Gallery at `{slug}/photographs/`, fancybox anchors grouped Gallery / Official / Construction, full-size at `/assets/img/temples/{slug}/{slug}-{id}.jpg`. Server 406s non-browser clients, so every fetch sends a browser User-Agent. Full-size photos are typically 1715x1200 to 2500x1520 but a 300x300 outlier was observed, hence the script-enforced pixel floor (long >= 1200, short >= 800). Load-more pagination is not implemented; the first page carries 80-110 images, which is plenty. robots.txt absent.
- **Known limit.** Only the gallery's first page load is read. Acceptable at current volumes.
- **Marker taxonomy and pipeline renames (20 Aug 2026, Evan, superseding the first unstarred-but-unbuilt rule from earlier the same day).** `*` = under construction or announced with a verified official render (render is the only ref, no top-up). `**` = announced with no render released (nothing usable; recheck the Official section on later sweeps and downgrade to `*` when a render appears). When the sweep discovers a folder's marker is wrong or missing, it fixes the marker itself: place.py renames the folder while moving it to READY, driven by the selection's `mark` field. The asterisk markers are the only part of a folder name the pipeline may ever change. It still never web-hunts for photos of a building that does not exist.
- **Render corroboration (20 Aug 2026, Evan).** Websites mislabel renders (a page can caption another temple's rendering with this temple's name). The temple site's own Official section is the trusted source. Web-sourced renders need an official Church source tying the image to this temple's name, plus a design cross-check; corroborating URLs go in the report. When in doubt, leave it out: `**` plus a shortfall note beats a wrong render.
- **Framing rule (20 Aug 2026, from Evan during the first sweep).** The whole temple must be in frame. Any image where part of the building (wing end, spire tip, base) is cut off by the frame edge fails, regardless of how good the rest of the shot is.
- **Slug convention correction (20 Aug 2026, first sweep).** Slugs keep periods from the official name: `st.-paul-minnesota-temple`, not `st-paul-minnesota-temple`. The site soft-404s unknown slugs with HTTP 200 and a generic page title, so a status check cannot validate a slug; validate by content (`gallery.py list` failing with "No fancybox images found" is the working signal).
